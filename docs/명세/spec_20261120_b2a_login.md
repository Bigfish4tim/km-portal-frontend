## 0. 한 줄 목적

직원이 새 시스템에 **로그인**하고, 임시 비밀번호이거나 3개월이 지났을 때 **변경 창**에서 비밀번호를 바꾸고, 로그인한 뒤 **본인 비밀번호를 바꾸고 로그아웃**할 수 있게 한다. 화면의 구성 · 문구 · 흐름은 레거시를 따른다.

## 3. 계약 — 구현 전에 백엔드 코드에서 직접 다시 확인한다

정본: 백엔드 2e 구현보고 2장 · `controller/AuthController.java` · `dto/common/LoginFailureReason.java` · `dto/common/ApiResponse.java` · `util/PasswordPolicy.java` · `docs/규약/2026-10-23_응답규약.md` §4-0. 아래와 다르면 **코드를 따르고 보고한다.**

### 3-1. 엔드포인트

| 함수(`src/api/authApi.ts`) | 요청 | 성공 | 토큰 헤더 |
|---|---|---|---|
| `login` | `POST /api/auth/login` `{username, password}` | 200 봉투 · `data`: `accessToken` · `refreshToken` · `tokenType` · `expiresIn` · `user` | 붙이지 않는다 |
| `refresh` | `POST /api/auth/refresh` `{refreshToken}` | 200 봉투 · `data`: `accessToken` · `tokenType` · `expiresIn`(새 refresh 토큰 없음) | 붙이지 않는다 |
| `fetchMe` | `GET /api/auth/me` | 200 봉투 · `data` = `user` 와 같은 모양 | 붙인다 |
| `changeExpiredPassword` | `POST /api/auth/password/expired` `{username, currentPassword, newPassword}` | 200 봉투 · `data` null · 토큰 없음 | 붙이지 않는다 |
| `changeOwnPassword` | `PUT /api/auth/password` `{currentPassword, newPassword}` | 200 봉투 · `data` null | 붙인다 |
| `logout` | `POST /api/auth/logout` | 200 봉투 | 붙인다(있으면) |

- `user` 의 키: `userId` · `username` · `email` · `fullName` · `department` · `position` · `phoneNumber` · `isActive` · `isLocked` · `lastLoginAt` · `createdAt` · `roles[]`(`roleId` · `roleName` · `displayName` · `priority`) · `primaryRole` · `primaryRoleDisplayName`(뒤의 둘은 없을 수 있다).
- 봉투의 `timestamp` 는 타입을 `unknown` 으로 두고 읽지 않는다. `failure` 키는 타입에 넣지 않는다.
- 토큰은 **불투명한 문자열**로 다룬다. 풀어서(decode) 읽지 않는다.

### 3-2. 로그인 · 만료 변경의 401 (백엔드 2e 보고 2-1)

| `errorCode` | `message`(서버 문구) | `data` | 화면의 동작 |
|---|---|---|---|
| `USER_NOT_FOUND` | 해당하는 아이디가 없습니다. | null | 확인 창에 문구 그대로 |
| `INVALID_CREDENTIALS` | 세 줄(아래) | `{failedAttempts, lockThreshold}` | 확인 창에 **세 줄을 세 줄로** |
| `ACCOUNT_DISABLED` | 비활성화된 계정입니다. 관리자에게 문의하세요. | null | 확인 창에 문구 그대로 |
| `ACCOUNT_LOCKED` | 잠긴 계정입니다. 관리자에게 문의하세요. | null | 확인 창에 문구 그대로 |
| `PASSWORD_EXPIRED` | 비밀번호가 만료되었습니다. 재설정이 필요합니다. | null | 🔴 로그인 화면에서만: 확인 창 없이 **변경 창으로 간다** |
| `AUTHENTICATION_FAILED` | 인증에 실패했습니다. 다시 시도해주세요. | null | 확인 창에 문구 그대로 |

틀린 비밀번호의 `message` — 세 줄이 줄바꿈 문자(`\n`)로 이어져 온다.

```
비밀번호가 일치하지 않습니다.
비밀번호가 5회연속 틀리면 로그인 계정이 잠깁니다.(N번 오류)
비밀번호는 대소문자를 구분합니다. 확인 하시고 다시 시도해 주세요.
```

- 🔴 **분기는 `errorCode` 로만 한다. 문구를 비교하지 않는다.** 화면은 서버의 `message` 를 그대로 보여 준다. 위 문구를 화면 코드에 다시 적지 않는다(숫자 `N` · `5` 를 화면이 끼워 넣지 않는다 — 서버가 완성해서 준다).
- `data.failedAttempts` · `data.lockThreshold` 는 타입에만 적고 **화면 표시에 쓰지 않는다**(문구에 이미 들어 있다. 둘을 따로 쓰면 어긋날 자리가 생긴다).
- 5번째 실패의 응답도 `INVALID_CREDENTIALS`("5번 오류")다. 그다음 시도부터 `ACCOUNT_LOCKED` 다. 화면이 횟수를 세어 미리 "잠김" 을 말하지 않는다.
- 만료 변경 API 는 `PASSWORD_EXPIRED` 를 주지 않는다(그 API 에서는 정상 흐름이다). 현재 비밀번호를 틀리면 `INVALID_CREDENTIALS` 이고 **로그인과 한 횟수로** 센다.
- `PASSWORD_EXPIRED` 는 비밀번호가 **맞은 뒤에만** 온다. 임시 비밀번호일 때와 3개월이 지났을 때가 같은 코드 · 같은 창이다.

### 3-3. 그 밖의 실패

| 경우 | 응답 |
|---|---|
| 빈 칸 | 400 `ProblemDetail` |
| 새 비밀번호의 규칙 위반(3-4) · 변경 대상이 아닌 계정의 만료 변경 | 400 봉투 `ILLEGAL_ARGUMENT` — `message` 앞에 "잘못된 요청 매개변수입니다: " |
| 본인 변경에서 현재 비밀번호 틀림 | **400** 봉투(401 이 아니다 · 실패 횟수에 넣지 않는다). 🔴 `errorCode` 와 문구는 코드에서 확인해 보고에 적는다 |
| 보호 API 의 401 | 토큰 만료와 계정 상태가 구별되지 않는다. **상태 코드 401** 로만 판별한다(`CLAUDE.md` 6-3) |

### 3-4. 비밀번호 규칙 여덟 줄 (백엔드 2e 보고 2-2 · `util/PasswordPolicy`)

위반은 **순서가 앞선 것 하나**만 온다.

| 순서 | 규칙 | 위반 문구 | 화면의 사전 검사 |
|---|---|---|---|
| 1 | 비어 있지 않다 | 비밀번호는 필수 입력 항목입니다. | 한다 |

| 4 | 영문 · 숫자 · 특수문자가 셋 다 있다 | 영어, 숫자, 특수문자가 포함되어야 합니다. | 한다 |

### 4-2. `src/api/http.ts` — 인터셉터 (`CLAUDE.md` 6-3 의 다섯 줄을 그대로 구현)

- **요청**: 액세스 토큰이 있으면 `Authorization: Bearer …` 를 붙인다. 🔴 `login` · `refresh` · `changeExpiredPassword` 에는 **붙이지 않는다.**
- **응답 401**
  1. 위 세 요청의 401 은 그대로 돌려준다(재발급을 시도하지 않는다).
  2. 그 밖의 401 이고 재발급용 토큰이 있으면 `refresh` 를 부른다. 🔴 동시에 여러 요청이 401 을 받아도 `refresh` 는 **한 번만** 나간다.
  3. 성공하면 새 액세스 토큰으로 원 요청을 **한 번만** 다시 보낸다. 다시 401 이면 포기한다(요청에 "이미 재시도함" 표시를 둔다).
  4. 재발급이 실패하거나 재발급용 토큰이 없으면: 토큰을 지우고, 스토어를 로그아웃 상태로 만들고, 로그인 화면으로 보낸다(지금 주소를 `redirect` 로 붙인다 — 4-6).
- 인터셉터는 문구를 만들지 않는다. 오류는 그대로 던지고 화면이 4-3 의 함수로 문구를 얻는다.
- `http.ts` 가 라우터 · 스토어를 직접 import 해서 순환 참조가 생기지 않게 한다(세션 종료 콜백을 등록하는 방식 등 — 방법은 자유).

### 4-3. `src/errors/` — 오류 → 화면 문구 (한 함수) · 화면이 만드는 문구

입력: 던져진 오류. 출력: `{ status, errorCode, message }`(`status` · `errorCode` 는 없을 수 있다).

| 경우 | `message` |
|---|---|
| 봉투(`message` 가 문자열) | 서버 문구 그대로(🔴 줄바꿈 문자를 지우거나 바꾸지 않는다) |
| 봉투이고 `errorCode` 가 `ILLEGAL_ARGUMENT` | 접두사 "잘못된 요청 매개변수입니다: " 를 떼고 뒤쪽. 접두사가 없으면 그대로 |
| `ProblemDetail`(`message` 없음 · `title`/`detail` 있음) | `TEXT.INVALID_INPUT` — 🔴 `detail` 을 그대로 보여 주지 않는다(`BR-4`) |

| 502 · 503 · 504 · 응답 없음 · 시간 초과 | `TEXT.SERVER_UNREACHABLE` |
| 500 | 봉투면 서버 문구 · 아니면 `TEXT.UNEXPECTED` |

**화면이 만드는 문구** — 한 파일에 모은다(B-1 이 `EnvCheckView.vue` 안에 둔 `TEXT` 도 그 자리로 옮긴다). 자리를 보고에 적는다.

| 이름 | 문구 |
|---|---|

| `REQUIRED_ID` · `REQUIRED_PASSWORD` | 아이디를 입력하여 주세요. · 비밀번호를 입력하여 주세요. |

| `TEMP_PASSWORD_NOT_READY` | 임시비밀번호 발급은 준비 중입니다. 관리자에게 문의하세요. |

| `INVALID_INPUT` · `NOT_FOUND` · `UNEXPECTED` · `SERVER_UNREACHABLE` | 입력값을 확인해 주세요. · 요청한 대상을 찾을 수 없습니다. · 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. · 서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요. |

- 🔴 2026-11-19 판의 `LOCK_HINT` · `FORGOT_HINT` · `SAME_AS_CURRENT` 는 **없다.** 잠금 안내는 서버의 세 줄에 들어 있고, "현재와 같음" 의 문구는 4-4 의 검사 모듈이 가진다.

**비밀번호 안내문**(변경 창 · 본인 변경 화면의 오른쪽)

1. {MIN}~{MAX}자의 영문, 숫자, 특수문자를 모두 조합하여 사용하실 수 있습니다.
2. 공백과 한글은 사용할 수 없습니다.
3. 같은 글자의 반복(aaa), 연속된 숫자/문자(123/abc)는 {RUN}글자 이상 사용할 수 없습니다.
4. 현재 사용하는 비밀번호와 최근 12개월 안에 사용한 비밀번호는 사용할 수 없습니다.
5. 생년월일, 전화번호, 이름 등 개인정보와 관련된 숫자는 다른 사람이 쉽게 알아낼 수 있으니 사용하지 마세요.
6. 비밀번호는 3개월마다 변경해야 합니다.

- `{MIN}` · `{MAX}` · `{RUN}` 은 4-4 의 상수에서 가져온다(문구와 규칙이 어긋나지 않게). 5 는 권고다(서버가 검사하지 않는다).
- ⚠️ 이 안내문은 레거시 안내문의 뜻을 새 규칙에 맞춰 쓴 것이다. 레거시의 글자 그대로가 아니다(준호님이 화면에서 본다 — 8장).

| 체크 | 로그인 성공 뒤(토큰을 저장한 다음) `window.open(목적지, 창 이름, 창 모양)` 으로 새 창을 연다. 🔴 `noopener` 를 주지 않는다 — 새 창이 `sessionStorage` 의 사본(재발급용 토큰)을 받아야 `restore()` 로 로그인 상태가 된다 |
| 목적지 | 4-7 의 검사를 통과한 내부 경로만. 🔴 바깥 주소로 `window.open` 을 부르지 않는다 |
| 새 창이 열린 뒤의 원래 창 | `endSession()` 으로 **자기 창의** 토큰 · `user` 를 비우고 로그인 화면에 남는다(칸을 비운다). `logout` API 는 부르지 않는다 |
| 새 창이 막혔을 때 | `window.open` 이 `null` 을 주면 확인 창에 `POPUP_BLOCKED` → 닫히면 같은 창에서 목적지로 간다 |
| 🔴 착수 확인 | Chromium 에서 "같은 출처 · `noopener` 없음" 의 `window.open` 이 `sessionStorage` 를 복사하는지 먼저 확인한다. 복사되지 않으면 **멈추고 보고한다**(토큰을 주소나 다른 저장소로 넘기는 우회를 만들지 않는다) |
| 창 이름 · 크기 | 자유(상수 한 곳). 보고에 적는다 |
