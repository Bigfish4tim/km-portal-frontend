## 4. 설계 판단과 근거

| # | 판단 | 근거 |
|---|---|---|
| 1 | 단위 테스트 설정을 `vite.config.ts` 의 `test` 칸에 두었다(별도 `vitest.config.ts` 없음) | 따로 두고 `./vite.config` 를 import 하면 Vite 8 이 "확장자 없는 import 는 앞으로 지원하지 않는다" 는 경고를 낸다. 한 파일이면 플러그인 · 별칭을 두 번 적지 않는다 |
| 2 | 프록시는 `target` 만 적었다(`changeOrigin` 없음) | 명세의 요구가 그것뿐이다. 브라우저가 보기에 같은 출처라 CORS 가 걸리지 않는다. 🔴 실제 백엔드를 상대로 한 확인은 준호님 확인 4번이다(이 세션은 백엔드를 띄우지 않는다) |

| 4 | 길이 문구는 상수(10 · 64 · 3)에서 조립한다 | 백엔드도 그렇게 만든다(`PasswordPolicy.java:53-58`). 대신 **테스트는 문구를 글자 그대로 따로 적어** 고정했다 — 구현의 상수를 가져다 비교하면 함께 틀려도 통과한다 |
| 5 | 아이디 비교는 소문자로 바꿔 비교한다 | 서버는 `equalsIgnoreCase`(`:112`)다. 그 검사까지 온 비밀번호는 전부 ASCII 라 결과가 같다 |
| 6 | 서버 확인은 `number \| null` 을 돌려준다(`null` = 응답 없음) | 명세: "상태 코드만 돌려준다 · 본문은 읽지 않는다". `validateStatus` 로 어떤 상태든 예외 없이 받는다 |
| 7 | 린트 L3 은 `no-restricted-imports`, L4 는 `no-restricted-globals` + `no-restricted-properties` 로 만들었다 | 맨이름(`localStorage`)과 `window.localStorage` · `document.cookie` 꼴을 모두 막는다. 허용 폴더는 그 규칙 블록의 `ignores` 로 뺀다 |
| 8 | Prettier 는 `*.md` 를 건드리지 않는다 | `npm run format` 이 문서(한글 표)와 `CLAUDE.md` 를 다시 쓰지 않게 한다 |
